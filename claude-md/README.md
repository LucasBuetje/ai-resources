# Context: the `CLAUDE.md` file

A `CLAUDE.md` is a plain Markdown file the agent reads at the **start of every session**. It's how you stop re-explaining yourself — write down how you work and what a project is, once, and the agent picks it up automatically.

Two levels, and they stack:

| | File | Scope | Holds |
|---|---|---|---|
| **Global** | `~/.claude/CLAUDE.md` | every project | how *you* work — your conventions, do's and don'ts |
| **Project** | `<project>/CLAUDE.md` | one folder | what *this* project is — data locations, build commands, codebook |

> [!TIP]
> Run `/init` in a new project and the agent drafts the project `CLAUDE.md` for you — it reads the codebase and writes down the structure, conventions, and key files. Edit from there.

The examples below are just that — **examples**. Take the rules that fit how you work, drop the rest, add your own.

## Example: global `~/.claude/CLAUDE.md`

```markdown
# Global instructions

## File safety
- Never delete files — move them to an `archive/` subfolder instead (`mv file archive/`).

## Scope
- Stay inside the project folder; don't reach above it. Ask me to copy in external files.

## Raw data — run, don't read
- Run a read-only script over raw data; don't read raw data files directly into the chat.

## Progress log
- Keep a running `log/current.md` per project: append what changed, why, and open questions as you go.
- Read it back at the start of each session. When I say "log", archive it to a timestamped file and start fresh.

## Surgical editing
- Change only what was asked. Don't refactor or reformat adjacent code. Match existing style.

## Minimal code
- Reuse before building: codebase → standard library → existing dependency → new code, in that order.
- Never cut corners on correctness, validation, error handling, or security.

## Be a partner, not a sycophant
- State disagreement early, with the reason. Don't open with reflex praise.

## Verification is code
- Save sanity-checks as named, re-runnable scripts. Test against ground truth, not a reconstruction.

## Writing
- German: gendergerechte Sprache with the colon (`Student:innen`); avoid anglicism calques.
- Don't overuse em-dashes.
```

## Example: project `<project>/CLAUDE.md`

```markdown
# Project: <paper / project name>

One or two lines: the research question, the deliverable, the current stage.

## Layout
- `data/raw/` — source data, never edit or overwrite
- `data/clean/` — derived, regenerated by `code/01_clean.R`
- `output/` — figures and tables, all script-generated
- `docs/codebook.md` — variable definitions; consult before referencing any variable

## Conventions
- R 4.4; always recompile the LaTeX doc after editing and fix until it builds
- Build the deck with the `/deck` skill
- Cluster standard errors at the `<unit>` level unless told otherwise
- Open questions live in `log/current.md`
```
